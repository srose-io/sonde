# Sonde 0.1: extract Loom.Probe into a standalone open-source tool

**Execution:** In Loom-managed sessions, execute with `loom-plan-execution`.

## Context

Sonde runs C# inside a live .NET process: a script is compiled out of process, sent in through a
startup-hook agent over a local socket, run against the host's real objects, and answered as JSON.
The mechanism shipped inside Loom in October 2026 as `Loom.Probe` and was proven on real services.
This plan turns that proven code into a standalone, MIT-licensed repository that a stranger can
use from the README and contribute to from a fork.

The repo today holds only `CLAUDE.md`, `LICENSE` (MIT), a stub `README.md`,
`docs/decisions/0001-charter.md` and `.loom/verify.json` whose three gates (`build`, `unit`,
`e2e`) pass vacuously until a solution exists. Read the charter first: it fixes the name, the
licence, the architecture, the transport, the security stance, the package split and the list of
non-negotiables, and it names the three questions still open (GitHub home, publish timing, NuGet
account).

The reference implementation is read-only, in the Loom checkout on this node
(`/home/slowdata/sroot/code/loom`):

| Loom source | Becomes |
|---|---|
| `tools/loom-probe/StartupHook.cs`, `ProbeBootstrap.cs`, `ProbeServer.cs`, `ProbeHost.cs`, `EvalRunner.cs`, `ProbeGlobals.cs`, `ProbeHarmony.cs`, `Hooks.cs`, `Taps.cs`, `ResultJson.cs`, `Protocol/*` | `src/Sonde.Probe/` |
| `tools/loom-probe.tests/*` (38 tests) | `tests/Sonde.Probe.Tests/` |
| `src/loom.api/Services/ProcessEval/ScriptCompiler.cs`, `ProbeClient.cs`, `ProbeLaunch.cs` (the env and runtimeconfig-template parts only) | `src/Sonde/` |
| `src/loom.api/Services/ProcessEval/ProcessEvalService.cs` (the compile-then-run flow, minus HTTP status mapping) | `src/Sonde/` (`SondeSession` or similar) |
| `docs/responses/dotnet-eval-tunnel.md` | the "what the CLR allows" section of `docs/architecture.md` |

What stays in Loom and must not be carried over: `ProbeLocator` (toolkit paths), `ProbeStatusCache`,
the `dotnetProbe` metadata opt-in, the admin gate, the audit log, every `LOOM_` prefix, every
`[Loom.Probe]` log tag, the `loom.probe.*` Harmony ids, the Loom-specific dates and node names in
code comments. Comments may keep the *lesson* ("a child that inherits the variables binds the same
socket") without the Loom war story.

## End state

A person with only the .NET SDK installed can, on a clean machine, follow the README and in five
minutes:

```
dotnet tool install -g sonde
sonde run -- dotnet run --project MyApp            # or: sonde env, then launch however they like
sonde eval <target> 'return g.Resolve<IConfiguration>()["Logging:LogLevel:Default"];'
```

and get JSON back. Every charter non-negotiable is a named test. Four packages (`Sonde.Probe`,
`Sonde`, `sonde`, `Sonde.Mcp`) build deterministically with SourceLink from one version, and a
tag publishes them to NuGet. CI proves the OS × .NET matrix (Linux, macOS, Windows × .NET 8, 9, 10)
with a real end-to-end job. The docs site is generated from the XML docs plus `docs/`.

Verification: `loom-verify` full tier PASS (`build`, `unit`, `e2e` gates in `.loom/verify.json`),
plus a green GitHub Actions run once the repo is pushed. The e2e suite in `tests/Sonde.EndToEnd`
is the real proof: it launches the samples with the probe and evals into them.

## Constraints

- Everything in the charter's "Decisions already made" table is fixed. Do not re-open it.
- **Nothing Loom-specific leaks.** No `LOOM_` variables (the endpoint variable is
  `SONDE_ENDPOINT`), no `[Loom.Probe]` tags (`[Sonde]`), Harmony ids `sonde.*`, no Loom mention in
  user-facing docs beyond one line in the README ("Sonde was born in Loom, where it ... ") and the
  charter ADR.
- **Non-negotiables each get a test** named for the scar, in `tests/Sonde.Probe.Tests` or
  `tests/Sonde.Tests`. The list is in the charter; S2 enumerates the test names.
- **The `StartupHook` type stays in the global namespace** with `public static void Initialize()`.
- **`Sonde.Probe` targets `net8.0`** (the lowest supported host; a startup hook built for 8 loads
  into 9 and 10 hosts, the reverse does not). It references only the shared framework plus
  `Lib.Harmony >= 2.4.2`. DI abstractions come from a `PackageReference` to
  `Microsoft.Extensions.DependencyInjection.Abstractions` with `ExcludeAssets="runtime"` so the probe
  binds to whichever copy the host already loaded, never ships its own. (Loom used the ASP.NET
  shared framework; Sonde must also work in a worker service that has no ASP.NET.) This is a design
  choice: record it as ADR 0002 in S2.
- **The script's globals type is `Sonde.Probe.ScriptGlobals`** (was `ProbeGlobals`), the wrapper
  type `SondeScript`, entry method `Run`. Script-facing names (`g.Services`, `g.Resolve<T>()`,
  `g.Scope()`, `g.Vars`, `g.Log`, `g.Cancellation`, `g.Hook`, `g.Unhook`, `g.UnhookAll`, `g.Tap`,
  `g.Tapped`, `g.Untap`) are kept exactly; a Loom user's scripts should port with no edits beyond
  the `using`.
- **Wire protocol** is Loom's (4-byte little-endian length + UTF-8 JSON, one request per
  connection, kinds `Hello`/`Status`/`Run`) with these renames: `ProbeVersion` → `SondeVersion`.
  `docs/protocol.md` is the spec and the tests in `Sonde.Probe.Tests` assert the exact bytes of a
  frame so a non-.NET client could be written from the doc.
- Only the .NET 9 SDK is installed on this node. Local builds and the local e2e run prove net9
  only; the 8 and 10 columns are CI's. Every project that must build locally targets `net9.0` or
  `net8.0`; nothing locally requires the 10 SDK. Use `global.json` with `rollForward: latestFeature`
  per major so the matrix can pin the SDK it installs.
- Analyzers on (`Microsoft.CodeAnalysis.NetAnalyzers` at `AnalysisLevel=latest-recommended`,
  `EnforceCodeStyleInBuild`), `TreatWarningsAsErrors`, `Nullable` enable, `Deterministic`,
  `ContinuousIntegrationBuild` in CI, SourceLink, `PublicAPI.Shipped.txt`/`Unshipped.txt` via
  `Microsoft.CodeAnalysis.PublicApiAnalyzers` on every packable project.
- `dotnet test` one invocation at a time on this node (shared machine); the e2e suite serialises
  its own process launches.
- Tests before behaviour (`test-driven-development`). The verify runner's verdict is the evidence
  for every slice's done-claim; a slice ends with a commit on `main`.
- Do not push until S10 asks Spencer the three open questions. Everything up to that point is
  local commits on `main`.
- Out of scope (charter): hot reload, profiler attach, a web UI, auth, Mono/NativeAOT.

## Risks and unknowns

- **DI capture in a non-ASP.NET host.** Loom's Harmony postfix on `ServiceProvider`'s constructor
  was best-effort and fell back to the ASP.NET request observer. The worker sample has no ASP.NET,
  so the Harmony path must actually work there, or `SondeHost.Register(host.Services)` must be
  the documented one-liner for worker services. S6's e2e test decides which; the docs say what was
  found.
- **Harmony on .NET 10 CI.** 2.4.2 is the floor per the charter. If the `MONOMOD_DMD_TYPE`
  module-initializer trick is still needed, keep it with its reason in a comment; test on the
  matrix.
- **`dotnet watch` in CI.** The runtimeconfig-template route needs a `dotnet watch` run inside the
  e2e job. It is slow (a watcher plus a build). Give it its own test with a generous timeout and
  mark it so it can be filtered out locally.
- **Idle-cost measurement** must be a CI job that launches a sample with and without the probe and
  reports RSS delta and thread delta into the job summary. It is an informational number, not an
  assertion with a tight threshold (noise); assert only a loose ceiling (e.g. < 40 MB).
- **MCP SDK.** `Sonde.Mcp` uses the official `ModelContextProtocol` NuGet package. Its API has moved
  between releases; pin the version that `dotnet add package` resolves at S7 time and note it in
  the ADR for the MCP surface.
- **System.CommandLine** is still prerelease-shaped in places. Pin a version in
  `Directory.Packages.props`; central package management from S1 so bumps are one line.

### S3 — `Sonde` client library: compiler, client, launch helpers, session

**Outcome.** `src/Sonde` compiles a script against a Hello's assembly list, talks the protocol
over a socket or pipe, and knows how to set a launch up so the hook is delivered through both the
environment and a runtimeconfig template. A `SondeSession`-style type does the whole
hello → compile → run flow and returns a typed result.

**Touchpoints.**
- `src/Sonde/ScriptCompiler.cs` (preamble names `Sonde.Probe` and `SondeScript`; reference
  resolution with the siblings-on-disk rule and the `MaxSiblingsPerDirectory` guard; reference
  cache keyed by mtime+length), `ScriptCompileResult`, `ScriptDiagnostic`.
- `src/Sonde/ProbeClient.cs` (`HelloAsync`, `StatusAsync`, `RunAsync`; Unix socket / named pipe).
- `src/Sonde/Launch.cs`: `Endpoint.ForProcess(name)` (the socket-path-length fallback: readable
  path, then hashed in the same directory, then hashed under temp; Windows: a pipe name),
  `Launch.ApplyEnvironment(env, probeDllPath, endpoint, runtimeConfigTemplate?)`,
  `Launch.WriteRuntimeConfigTemplate(dir, name, probeDllPath, projectDir?)`,
  `ProbeAssembly.Path` (where `Sonde.Probe.dll` ships inside the `Sonde` package: as a content
  file under `sonde-probe/` so the client can hand its path to a launch).
- `src/Sonde/SondeSession.cs`: `EvalAsync(endpoint, script, options)` →
  `EvalResult { Result (JsonNode?), Logs, Exception, ElapsedMs, TimedOut, LiveContexts }` and typed
  failures (`CompileFailed(diagnostics)`, `Busy(since)`, `Unreachable(reason)`, `ProtocolError`).
  No HTTP status codes; the CLI and MCP map these.
- `tests/Sonde.Tests`: compiler diagnostics map to script line numbers (`#line`), siblings on disk
  are referenced (a script naming an assembly the test host has not loaded compiles), the
  reference cache hits on a second compile, `ApplyEnvironment` appends with the path separator,
  `WriteRuntimeConfigTemplate` merges over an existing template and does not duplicate the hook,
  `Endpoint.ForProcess` never exceeds 107 bytes on POSIX, and a loopback test that starts the
  listener in-process and round-trips Hello/Status/Run through `ProbeClient`.
- `PublicAPI.Unshipped.txt` lists every public member added.

**Verification.** `loom-verify` full PASS; `tests/Sonde.Tests` green.
